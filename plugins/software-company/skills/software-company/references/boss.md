# Boss

Take a concrete goal through planning, implementation, testing, and review in the current Codex App chat and workspace. A request such as `$software-company-boss Build a temperature conversion tool` authorizes the in-scope local work. A question or a mode mention without a goal calls for an explanation or a brief.

1. If the user gives a destination, check it against the active workspace and the requested scope. For a new deliverable with no destination, choose an unused `projects/<project-slug>/` inside this workspace. If continuing specified existing work, respect its established location. Make reasonable, reversible assumptions for choices the brief leaves open and record them in the PRD.
2. In the same turn, use [Planning](plan.md) to write and verify the three planning files. Record the implementation location and observable acceptance criteria. The planning files are checkpoints for this run and evidence for the final report.
3. Continue directly through [Generate](delivery.md#generate), Testing and Review with the plan just written. Routine stage transitions need no further request. Pause only for a decision that materially changes the outcome, a required approval, or a blocker that prevents useful progress.
4. Return the planning files, implementation location, actual test outcomes, review findings, and any remaining work. Only call the result complete when the requested functionality and applicable checks have been delivered.

Use the signed-in App model and built-in tools throughout. Keep all edits within the approved project scope and follow the App's normal permission rules.
